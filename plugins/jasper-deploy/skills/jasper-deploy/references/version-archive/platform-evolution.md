# JasperReports Server Platform Support Evolution (4.7 - 10.1.0)

Distilled from the official Jaspersoft Platform Support PDFs (extracted text in doctext/).
Facts only from those documents; source file cited per row/claim as (filename without .txt).
Scope: commercial edition unless marked CE. "Repo DB" = databases the doc marks with
Type "Repository" (i.e. certified to host the JasperReports Server repository), as opposed
to Data Source only.

NOTE ON FIDELITY: these are PDF-to-text extractions; table columns (Certified vs
Compatible) are sometimes scrambled by the extraction. Version lists below come from the
Version column, which extracts cleanly. Where a Certified/Compatible distinction matters
and was legible, it is stated; otherwise treat entries as "listed as supported."

## 2. Breaking platform shifts (exact versions)

Java:
- Java 1.6 last listed at 6.1; dropped at 6.2 (Oracle JVM = 1.7/1.8) (jaspersoft_platform_support_v6.1, jaspersoft_platform_support_v6.2).
- Java 1.8 first certified at 6.1 (jaspersoft_platform_support_v6.1).
- Java 1.7 last listed at 6.4; 7.1 is Java 8 only (jaspersoft_platform_support_v6.4_0, jaspersoft_platform_support_v_7.1_0).
- Java 8 minimum build 1.8.0_163 first stated at 7.5 and repeated through 9.0 (tib_js-jrs_7.5_jaspersoft_platform_support-commercial-edition, js-jrs_9.0.0_platform-support-commercial).
- Java 11 first certified at 7.5 (tib_js-jrs_7.5_jaspersoft_platform_support-commercial-edition).
- Java 17 first certified at 8.2, with two hard constraints: runtime only, and only when JRS is deployed on Tomcat 9.0.x (js-jrs_8.2.0_platform-support-commercial-edition footnotes 9/10). Same constraints at 9.0 (js-jrs_9.0.0_platform-support-commercial).
- Java 8 and 11 dropped at 10.0.0; Java 17 becomes the baseline; Temurin 21 certified (js-jrs_10.0.0_platform-support-commercial_28Jan). 10.1.0 formalizes a 17/21 matrix across Oracle, Temurin, and Red Hat OpenJDK (js-jrs_10.1.0_platform-support-commercial).
- 32-bit JVM: last listed 6.3 ("32-bit or 64-bit"); 6.4 lists 64-bit only JDKs (jaspersoft_platform_support_v6.3, jaspersoft_platform_support_v6.4_0).

App servers:
- Tomcat 9 first supported at 7.2 (8.5.0-8.5.39 / 9.0.1-9.0.17) (jasperreports-server-platform-support-commercial-edition).
- Tomcat 8.5 demoted to Compatible at 9.0 (9.0.x Certified) (js-jrs_9.0.0_platform-support-commercial).
- Tomcat 9 to 10.1/11 (Jakarta namespace generation) at 10.0.0: only Tomcat 10.1.24+ and 11.0.11+ are listed; 8.5/9.0 disappear entirely (js-jrs_10.0.0_platform-support-commercial_28Jan).
- Tomcat 9.0.67 explicitly broken for 8.1: "JasperReports Server does not work with Version 9.0.67, due to Tomcat bug 66277" (tib_js-jrs_8.1.0_platform-support-commercial-edition).
- JBoss AS (community): last listed 6.2; WildFly first listed 6.3 (jaspersoft_platform_support_v6.2, jaspersoft_platform_support_v6.3).
- SpringSource tc Server: last listed 6.2 (jaspersoft_platform_support_v6.2).
- GlassFish: last listed 7.2 (4.1.2); gone at 7.5 (jasperreports-server-platform-support-commercial-edition, tib_js-jrs_7.5_jaspersoft_platform_support-commercial-edition).
- JBoss EAP 8.0 (Jakarta) replaces EAP 7.x at 10.0.0; WildFly jumps 18/19 to 36 (js-jrs_10.0.0_platform-support-commercial_28Jan).
- IBM WebSphere and Oracle WebLogic: last listed at 9.0 (WAS 9.0.5.5, WebLogic 14.1.1.0); both absent from 10.0.0 and 10.1.0 (js-jrs_9.0.0_platform-support-commercial, js-jrs_10.0.0_platform-support-commercial_28Jan).
- JBoss Web Server (JWS) 5.7.2 appears only at 9.0 (js-jrs_9.0.0_platform-support-commercial).
- Jetty is listed only as the JasperReports IO (Pro) / Web Studio container, from 7.2 (9.4.x) through 10.1 (12.0.x), never for JRS itself.

Report export / rendering engine:
- Adobe Flash listed as required for Professional Charts, Maps, and Widgets from 4.7 through 6.2; dropped at 6.3 (jaspersoft_platform_support_v4.7 footnote, jaspersoft_platform_support_v6.2, jaspersoft_platform_support_v6.3).
- Headless browser section (PhantomJS 1.9.8/2.1.1) first appears at 6.3; PhantomJS 2.1.1 through 7.5 (jaspersoft_platform_support_v6.3, tib_js-jrs_7.5_jaspersoft_platform_support-commercial-edition).
- PhantomJS replaced by Chromium at 7.9 (Chromium 80+); Chromium 85+ for 8.x; Chromium 116+ for 9.0/10.x (tib_js-jrs_7.9_platform-support-commercial-edition, tib_js-jrs_8.0.2_platform-support-commercial-edition_1, js-jrs_9.0.0_platform-support-commercial).

Browsers:
- Microsoft Edge first listed at 6.3 (jaspersoft_platform_support_v6.3).
- Internet Explorer last listed at 7.5 (IE 11); absent from 7.9 on. IE compatibility mode was never supported (footnote in 6.3-7.5 docs) (tib_js-jrs_7.5_jaspersoft_platform_support-commercial-edition, tib_js-jrs_7.9_platform-support-commercial-edition).

## 3. Migration pain points and what the docs say to do

- Tomcat 9 to 10.1/11 + JBoss EAP 8.0 at 10.0.0 (Jakarta EE namespace generation). What breaks: any deployment on Tomcat 8.5/9.0, WebSphere, WebLogic, or JWS has no supported target in 10.x - those servers simply vanish from the support list. Doc remedy: none given beyond the new list; plan re-hosting to Tomcat 10.1.24+/11.0.11+, WildFly 36, or JBoss EAP 8.0 (js-jrs_10.0.0_platform-support-commercial_28Jan).
- Java 8/11 to 17/21 at 10.0.0. What breaks: any JVM below 17. Transitional state: on 8.2 and 9.0, Java 17 is "supported only in runtime, and when JasperReports Server is deployed on Tomcat 9.0.x", and Java 11 "supported in runtime, for source build use Java 8 compatibility mode of JDK 11 (source and target)" - i.e. custom-code builds stayed on Java 8 bytecode through the 8.x/9.0 era (js-jrs_8.2.0_platform-support-commercial-edition footnotes, js-jrs_9.0.0_platform-support-commercial). At 10.1, only Oracle/Temurin/Red Hat OpenJDK are Certified; other OpenJDK distros are expected-Compatible but not validated (js-jrs_10.1.0_platform-support-commercial).
- PhantomJS to Chromium at 7.9 (headless export of dashboards/charts). What breaks: PhantomJS-based export configs. Doc remedy (8.2+): auto-detection works only for Chrome/Chromium; a different binary path can be set in the installer; to use another browser (e.g. Edge) set the path in js.config.properties (js-jrs_8.2.0_platform-support-commercial-edition footnote 3, repeated in 9.0/10.x).
- MySQL 8.0 on WebLogic (7.9 through 9.0): "MySQL 8.0 Native Driver is not supported on WebLogic for this release, but MariaDB 2.5.3 driver is supported" - swap the JDBC driver when hosting the repo or data sources on MySQL 8 under WebLogic (tib_js-jrs_7.9_platform-support-commercial-edition, js-jrs_9.0.0_platform-support-commercial).
- Tomcat 9.0.67 (8.1 era): do not use; JRS does not work with it due to Tomcat bug 66277 - pin to another 9.0.x patch (tib_js-jrs_8.1.0_platform-support-commercial-edition).
- ElasticSearch 7.6 (7.9-8.0 era): JRS has documented limitations with ElasticSearch; "For ElasticSearch 7.6 users, refer to the Elastic website for instructions on how to upgrade to ElasticSearch 7.9" (tib_js-jrs_7.9_platform-support-commercial-edition; 8.0 doc says upgrade "from ElasticSearch 7.6").
- Repo DB version cliffs: upgrading JRS can invalidate the repository host - e.g. moving to 8.1 drops SQL Server 2014; to 8.2 drops Oracle 12c/18c, PostgreSQL 9.x-11, DB2 10.5; to 10.0 drops MySQL 5.7 and PostgreSQL 12/13; to 10.1 drops MySQL 8.0. The docs give the lists only; the implied action is to upgrade the repository DB before or with the JRS upgrade (citations in section 2).
- 32-bit to 64-bit at 7.1: 32-bit WAR installs are no longer offered; migrate the host and JVM to x86-64 (jaspersoft_platform_support_v_7.1_0).
- Installer changes at 8.0.x: the Binary Installer (Tomcat+PostgreSQL bundle) "is intended for evaluation purposes only. To install JasperReports Server for enterprise production environments, use the stand-alone WAR file distribution, which is the official JasperReports Server installer"; binary installers are not updated post-release and "may contain components that can become insecure" (tib_js-jrs_8.0.2_platform-support-commercial-edition_1, repeated 8.1-10.1).
- Ubuntu: 18.04/20.04/22.04 LTS supported "only when deployed via buildomatic" - installer path not supported there (tib_js-jrs_7.5..., tib_js-jrs_8.1.0..., js-jrs_9.0.0...).
- OpenJDK vendor nuances (8.x-9.0): Eclipse OpenJ9 is a source-only distribution (also downloadable from IBM); HotSpot Corretto is "Only supported in JasperReports Server Cloud installations"; Oracle OpenJDK 11 is reference-implementation binaries with no security updates (tib_js-jrs_8.1.0_platform-support-commercial-edition footnotes).
- JDBC driver stack change at 10.0: the doc lists data sources "tested for Progress Driver replacement" (Elasticsearch, Neo4j, MongoDB, Hive, Impala, Cassandra, Spark SQL, Snowflake, Azure SQL, BigQuery, Autonomous REST JDBC) - the bundled Progress/DataDirect drivers are being replaced; REST API data source at 9.0/10.x is "Compatible and tested only for Progress driver" (js-jrs_10.0.0_platform-support-commercial_28Jan, js-jrs_9.0.0_platform-support-commercial).
- Old-generation quirks worth knowing for archaeology: JBoss Data Services 5.5.x JDBC driver "works only under Java 5 (not Java 6)" (4.7-6.4 docs); Adobe Flash required for Pro Charts/Maps/Widgets pre-6.3; IE compatibility mode never supported (jaspersoft_platform_support_v4.7, jaspersoft_platform_support_v6.4_0).
