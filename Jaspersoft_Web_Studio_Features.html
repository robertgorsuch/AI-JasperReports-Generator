Jaspersoft Web Studio

Detailed Feature & Functionality Summary — Browser-Based Report Designer

Jaspersoft Web Studio is the browser-based, zero-install report designer introduced into the Jaspersoft platform (JasperReports Server 9.x and carried forward in version 10). It brings the pixel-perfect report-authoring experience of the desktop Jaspersoft Studio directly into the web browser, running inside JasperReports Server itself. Report authors design, edit, preview, and publish JR7 .jrxml reports without installing the Eclipse-based desktop client, working against the server's own repository and data sources. It is a commercial (Professional / Enterprise) feature aimed at closing the gap between heavyweight desktop design and the server's no-code Ad Hoc editor — giving developers and power users full control over layout without a local install.

What Jaspersoft Web Studio Is

  • A web application embedded in JasperReports Server — opened from the server UI, no download or desktop install.
  • A WYSIWYG visual designer for pixel-perfect JR7 jrxml reports, running entirely in the browser.
  • Repository-native — opens, edits, and saves reports and resources directly in the server repository.
  • A modern, web-rendered counterpart to the desktop Jaspersoft Studio, sharing the same jrxml format and report model.

Why It Exists — Positioning

  • Removes the friction of installing and maintaining the Eclipse-based desktop Studio on every author's machine.
  • Bridges the spectrum between the no-code Ad Hoc Editor (business self-service) and full developer-grade pixel-perfect design.
  • Enables design from any OS or device with a browser — nothing to license, patch, or version locally.
  • Keeps authoring close to the server — same repository, data sources, and security context as runtime.

Design Environment

  • Visual drag-and-drop canvas with the standard report bands (Title, Page/Column Header & Footer, Group Header/Footer, Detail, Summary, Background, No-Data).
  • Palette of report elements and components to drag onto the canvas.
  • Properties panel for context-sensitive element attributes (position, size, font, style, formatting, hyperlinks).
  • Outline / report-structure tree for navigating bands, elements, fields, parameters, and variables.
  • Alignment, snapping, sizing, and z-order controls — the desktop layout conveniences in the browser.
  • Source / jrxml view for direct inspection and editing of the underlying XML where supported.

Report Building Blocks

  • Fields, Parameters, and Variables with calculation types (Sum, Average, Count, Highest/Lowest, etc.).
  • Expression editor for field/variable/conditional expressions and built-in functions.
  • Groups with headers/footers and subtotals.
  • Styles — named and conditional styles, plus references to shared style templates.
  • Subreports and dataset-bound components.

Components & Visualization

  • Tables, Lists, and Crosstabs (pivot tables with totals).
  • Charts — the platform chart types (JFreeChart and, on the commercial server, HTML5/Highcharts and Fusion).
  • Text fields, static text, images, shapes, frames, hyperlinks, and barcodes/QR.
  • Component configuration through the properties panel rather than hand-edited XML.

Data Connectivity

  • Designs against the server's existing data sources (JDBC, JNDI, Bean, virtual, Domains) — no local driver setup.
  • Query editor for the report's SQL/query, with field discovery from the result set.
  • Reuses repository data adapters and Domains as report data, keeping authoring and runtime aligned.

Preview, Publish & Lifecycle

  • In-browser live preview — fill the report against real data and view the rendered output without leaving the designer.
  • Server-side compile — the server validates and compiles the jrxml as part of save/preview.
  • Save directly to the repository — the report is immediately available to run, schedule, embed, or place on a dashboard.
  • Round-trips with desktop Studio — the same jrxml can be opened/edited in either tool.
  • Authoring respects the user's repository permissions and security context.

Strengths & Considerations

Strengths

  • Zero install / zero maintenance — nothing to deploy or patch on author machines.
  • OS- and device-independent — design from anywhere with a browser.
  • Repository- and security-native — authoring uses the same resources and permissions as runtime.
  • Lower barrier for power users who need more than Ad Hoc but don't want the full Eclipse client.
  • Same jrxml model — full interoperability with desktop Studio and the server.

Considerations

  • It is a commercial feature — not part of the Community edition.
  • The Eclipse plug-in ecosystem and certain advanced/custom-extension workflows remain the domain of the desktop client.
  • Authoring runs inside the server, so capabilities track the server's installed components and version.
Relation to this toolkit: Jaspersoft Web Studio is the interactive, in-browser way to author the same JR7 jrxml that the /jasper-deploy skill produces and deploys by script (scaffold_jrxml.py → compile_jrxml.ps1 → deploy_report.ps1) against the local jasperserver-pro install. The three authoring paths are complementary: Web Studio (browser, pixel-perfect, no install), desktop Jaspersoft Studio (full Eclipse tooling and extensions), and the scripted pipeline (reproducible/CI deployment) — all producing the identical jrxml report model in the server repository.
