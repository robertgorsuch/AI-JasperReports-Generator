# Seed data: the two sample databases this skill depends on

Nearly every example in `SKILL.md`, the reference reports under `report\`, and
`scripts/smoke_test.ps1` query one of two local PostgreSQL databases. A fresh
clone of this machine's setup MUST have both databases loaded, and both bound as
JasperReports Server datasources, or the examples and the smoke test will fail at
fill time with empty results or a `relation does not exist` error.

Connection used everywhere (PostgreSQL on this machine):
- host `localhost`, port `5432`, user `postgres`
- set `$env:PGPASSWORD = "postgres"` before running psql / the Python scaffolders

JRS datasource bindings (created once with `scripts/create_datasource.ps1`, or
the shipped sample for Foodmart):
- foodmart           -> `/public/Samples/Data_Sources/FoodmartDataSource`
- postgis_34_sample  -> `/datasources/postgis_34_sample`

---

## 1. `foodmart` -- the JasperReports / Mondrian "FoodMart" sample

**Purpose.** The standard JasperReports Server / Mondrian *FoodMart* demo
dataset (a fictional grocery retailer). It backs all the `report\foodmart\*`
reports, the Foodmart dashboard, the single-table Domain example, and the
Mondrian/OLAP example. It is the same FoodMart schema JasperReports Server ships
its own samples against, which is why it is bound at the standard sample URI
`/public/Samples/Data_Sources/FoodmartDataSource`.

**Key tables** (41 tables in `public`):
- `sales_fact_1998`, `sales_fact_1997` -- the fact tables (store_sales,
  store_cost, unit_sales, keyed by product/customer/store/time/promotion).
  Reports default to **1998** (see the "reports use current year" memo: show the
  current year in labels, data still comes from the 1998 table).
- `product`, `product_class` -- product dimension + family/department/category
  hierarchy.
- `store` -- store dimension (region, city, store type).
- `time_by_day` -- date dimension (the_date, the_month, quarter, the_year).
- `customer` -- customer dimension.
- `promotion` -- promotion dimension (used by the promotion-effectiveness report).

**Verification (psql):**
```powershell
$env:PGPASSWORD = "postgres"
# count public tables -- expect 41
psql -h localhost -U postgres -d foodmart -t -c `
  "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
# confirm the primary fact table exists and has rows
psql -h localhost -U postgres -d foodmart -t -c `
  "SELECT to_regclass('public.sales_fact_1998') IS NOT NULL AS has_fact, count(*) FROM sales_fact_1998;"
# confirm a couple of dimension tables
psql -h localhost -U postgres -d foodmart -t -c `
  "SELECT to_regclass('public.product'), to_regclass('public.store'), to_regclass('public.time_by_day');"
```

**(Re)loading.** FoodMart is not generated by anything in this repo -- obtain it
from the upstream sample data:
- Mondrian ships the canonical FoodMart dataset and a loader (`MondrianFoodMartLoader`)
  plus a `FoodMartCreateData` SQL/JSON source. Obtain it from the Mondrian /
  Pentaho distribution (`mondrian-data-foodmart`) and load into a fresh `foodmart`
  database, or
- the JasperReports Server installer / sample-data bundle includes the same
  FoodMart schema used by its Samples; obtain the FoodMart DDL + data from the
  JasperReports Server sample-data package and restore it into PostgreSQL.

If the exact reload procedure is unknown on a given machine, obtain the dump from
one of the sources above rather than reconstructing tables by hand. After
loading, (re)create the JRS binding only if the shipped sample datasource is
missing:
```powershell
& scripts\create_datasource.ps1 -Uri /public/Samples/Data_Sources/FoodmartDataSource `
    -Label "Foodmart" -Database foodmart -DbUser postgres -DbPassword postgres
```

## 2. `postgis_34_sample` -- the PostGIS TIGER geocoder sample

**Purpose.** The PostGIS TIGER geocoder sample database (the project's namesake,
"tx-geocoder"). It backs the geocoder / Texas reports (`report\county_summary*`,
`report\tx_*`, `report\metro_population*`, the FusionMaps Texas choropleth) and
is the default database for `scaffold_jrxml.py`. Bound in JRS as
`/datasources/postgis_34_sample`.

**Key tables** (52 tables across the `tiger`, `tiger_data`, and `public`
schemas -- the standard TIGER geocoder layout):
- `tiger.county`, `tiger.state`, `tiger.place`, `tiger.zip_lookup`,
  `tiger.loader_*` -- the national TIGER reference + loader-control tables.
- `tiger_data.tx_edges`, `tiger_data.tx_faces`, `tiger_data.tx_addr`,
  `tiger_data.tx_featnames`, `tiger_data.tx_bg` (block groups), etc. -- the
  loaded **Texas** (state FIPS `48`) geometry/address data.
- the PostGIS extension objects (`spatial_ref_sys`, etc.) in `public`.

**Verification (psql):**
```powershell
$env:PGPASSWORD = "postgres"
# count tables across all schemas -- expect 52
psql -h localhost -U postgres -d postgis_34_sample -t -c `
  "SELECT count(*) FROM information_schema.tables WHERE table_schema IN ('tiger','tiger_data','public');"
# confirm the geocoder reference table exists (and Texas is present)
psql -h localhost -U postgres -d postgis_34_sample -t -c `
  "SELECT to_regclass('tiger.county') IS NOT NULL AS has_county,
          count(*) FILTER (WHERE statefp='48') AS tx_counties FROM tiger.county;"
# confirm the loaded Texas edge data
psql -h localhost -U postgres -d postgis_34_sample -t -c `
  "SELECT to_regclass('tiger_data.tx_edges');"
```

**(Re)loading.** This DB is produced by the **PostGIS Tiger geocoder** loader,
not by anything in this repo -- obtain the procedure from the PostGIS Tiger
geocoder documentation:
1. Create a PostGIS-enabled database and enable the geocoder extensions:
   `CREATE EXTENSION postgis; CREATE EXTENSION fuzzystrmatch;
    CREATE EXTENSION postgis_tiger_geocoder;` (and `address_standardizer` if used).
2. Generate the nation + state load scripts with the geocoder's loader functions
   (`Loader_Generate_Nation_Script`, `Loader_Generate_Script` for state `'TX'`),
   which download the Census TIGER shapefiles and `shp2pgsql` them into
   `tiger_data`. Obtain the exact generator invocation and prerequisites
   (`wget`/`unzip`/`shp2pgsql` on PATH, the `loader_platform` row) from the
   PostGIS Tiger geocoder docs -- do not hand-write the COPY/shp2pgsql commands.

After loading, (re)create the JRS binding if missing:
```powershell
& scripts\create_datasource.ps1 -Uri /datasources/postgis_34_sample `
    -Label "PostGIS 34 Sample" -Database postgis_34_sample -DbUser postgres -DbPassword postgres
```
